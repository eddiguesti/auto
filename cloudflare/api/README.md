# Native D1 staging slice

`../api-staging.js` is an independently configured native Fetch Worker. It executes explicit D1 SQL and is never wired into the production frontend binding. `wrangler.api-staging.jsonc` disables workers.dev, preview URLs and routes, uses an obvious local-only D1 ID, and contains no secrets. No part of this slice has been deployed.

## Implemented HTTP contracts

Every route below is supported under both `/api` and `/api/v1` with private/no-store responses. Registration, login and email verification are public but require the trusted ingress identity provider described below; other routes require authenticated owner scoping.

`GET /payments/products` is also public and needs no database, signing secret or identity provider. Node checkout and both public APIs use `packages/shared/payment-catalog.js` for the same immutable prices, IDs and display fields. Subscriptions remain `checkoutAvailable:false`. Other availability flags describe the existing source catalog; **native checkout/payment mutations remain unsupported501**, so this endpoint supplies prices rather than payment parity.

Unsupported routes return 501 `NOT_MIGRATED`; protected payment/account/refund/admin route families still require authentication and full scope before that response. Source story routes permit scoped magic-link tokens, so the slice preserves that permission. None of these unsupported endpoints performs payment, account or admin actions.

## Security and stored values

- Passwords remain bcrypt12 with `bcryptjs`'s browser bundle and WebCrypto randomness. Actual workerd tests verify imported `$2a$`, `$2b$`, `$2y$` hashes without rewriting them and create hashes accepted by Node. Source password trimming and bcrypt's 72-byte behavior are preserved. CPU-heavy bcrypt requires a **Paid Workers plan**; the staging configuration requests a 5-second CPU budget. Local registration including D1 and email took approximately 0.6–1.1 seconds, which is wall time rather than hosted CPU evidence. Inventory imported bcrypt costs and profile deployed staging CPU before enabling real traffic; Free's CPU budget is insufficient for this design. No live plan or budget has been verified.
- Public auth uses an atomic D1 fixed window of **10 attempts per 900 seconds**, shared across login/register and both prefixes, matching the actual source limiter (its Swagger text says five). Verification also uses this protection as intentional hardening. `AUTH_CLIENT_ID` is a mandatory trusted service binding: absent/rejecting provider or D1 rate-table failure returns503 before hashing. The API forwards only `X-EasyMemoir-Client-Identity` and an `X-EasyMemoir-Auth-Path` computed from the request URL to `https://auth-identity.internal/verify`. The provider must verify the signed ingress assertion and return `{subject:'ip:<canonical IPv4 or IPv6 /56>'}`. User JWTs, cookies, passwords, bodies and client IP headers never cross this binding. Client IP headers plus `request.cf` alone are insufficient evidence because same-zone Worker subrequests can change IP headers. Trusted ingress signing and WAF policy must be independently verified before deploying auth; test providers are harness-only bindings, not public bypasses. Expired rate-window cleanup remains to be scheduled.
- Verification email uses the existing Resend REST contract, `RESEND_API_KEY` and optional `EMAIL_FROM`; `APP_URL` defaults to the source site and must be HTTPS without credentials. A trusted `EMAIL_PROVIDER` service binding can supply the same contract. No missing-provider fallback pretends to send email. Registration preserves source success when delivery fails, with no sensitive email/token logging; resend verification is not yet ported, so reliable provider delivery is an acceptance prerequisite.

- Existing source-minted HS256 JWTs are verified with native Web Crypto. The verifier requires source-generated integer user ID, expiration and issue-time claims, honors `nbf`, checks canonical base64url and refuses unsigned/alternative algorithms. HMAC signatures are decoded as bytes, never UTF-8. No development bypass exists.
- Each authenticated request starts a D1 `first-primary` session. Single-token blacklist and user invalidation reads are part of the authoritative identity lookup; database errors fail closed. User invalidation uses issuance-second comparisons consistent with the source. Expired blacklist rows do not revoke current sessions; cleanup scheduling remains to be ported.
- `value-codecs.js` uses the reviewed source mapping. `style_applied` is TEXT, despite stale source JSDoc. Nullable booleans remain NULL or decode 0/1 to false/true. JSON text and exact decimal text stay unchanged in storage; unsafe numeric JSON decoding refuses loss rather than silently rounding.
- Imported TIMESTAMP wall-clock text and TIMESTAMPTZ UTC text retain all microseconds. API JSON converts dates to millisecond ISO strings like PostgreSQL's Node Date serialization. UTC is an explicit **local test policy**, not a verified claim about Railway's runtime. Source timezone cannot be confirmed until source access; production cutover must verify it. The Worker refuses a missing/unverified wall-clock policy. SQLite does not parse the exporter’s `+00` suffix directly, so revocation comparisons deliberately normalize that suffix to `Z` in SQL without modifying stored data.
- Node and native logout share ordinary JTI keys and `sha256:<hex>` keys for legacy JWTs without JTI. Both reject noncanonical base64url before fingerprinting. Compatibility applies to this refactored Node release; rollback to older Node code would lose legacy-token revocation enforcement. Database state must also be reconciled during any runtime rollback; compatible key formats do not synchronize separate databases.
- `story_outbox` is a new staging-only table, separate from the audited 48-table source schema. D1 `batch()` atomically writes the story and exact saved-content event payload. Consumer delivery, idempotency, chapter-completion/provider calls and operational retry handling remain necessary before deployment. Pending intent is not presented as completed AI work.

## Offline verification

```powershell
npm run test:cloudflare:api
npm run check:cloudflare:api
```

The tests build actual Workers, start workerd through the installed Miniflare, create real local D1 tables from the audited schema, and execute HTTP requests and repository statements. Auth tests cover browser bcrypt compatibility, native JWT minting accepted by Node, public-route validation, duplicate/concurrent registration, real game-state transaction rollback, atomic rate windows, trusted-provider privacy/failure, email-provider failure and one-time verification rollback. Story tests cover owner isolation, both prefixes, JWT signature/expiry, premium gates, real transaction rollback, concurrent upserts, exact imported date storage, scoped access, immediate logout, fingerprint logout and fail-closed revocation outages. They use synthetic local accounts and test secrets; no live source data, remote resources or DNS are touched.

For a separately provisioned staging environment, replace the local D1 sentinel, initialize the reviewed `../db/schema.sql` before applying **all** reviewed `migrations/*.sql` in order, and supply a staging `JWT_SECRET` through secrets/local ignored `.dev.vars`. Auth additionally requires a verified Paid Workers CPU budget, trusted ingress/identity-provider binding and a working email provider. Railway access remains necessary to audit imported hashes, source timezone and live account state; R2 activation remains necessary to copy and verify private media. Neither the local example ID nor test secrets belong in a deployed configuration. Do not change the default `wrangler.jsonc` API binding to this partial service.

Remaining auth features include Google OAuth, password reset/change, magic-link issuance/exchange, resend verification and user refresh/profile routes under `/auth`; unsupported auth routes return501 explicitly. Photo and account/onboarding handlers are integrated after authoritative authentication, with their bounded contracts covered separately. Payment/catalog/subscription/webhooks, voice/Telnyx, EPUB/audiobook jobs, entity/art consumers, remaining gamification, refunds, admin/account deletion, notifications, cron execution and production observability still require ports. See `../API_ARCHITECTURE.md` and the maintained readiness route inventory for cutover requirements.
