# Native generation jobs

Apply `cloudflare/api/migrations/0003_generation_jobs.sql` after the reviewed application schema. The API stores a job plus its outbox intent atomically. Queue messages contain only `{version:1,jobId}`; consumers read authoritative options/owner/state from D1. The queue does not carry memoir content or provider credentials.

Integration hooks:

- HTTP: `handlePublishingRoutes({request,env,db,path,user,claims,now})` in `cloudflare/api/publishing.js`. Authentication must already have resolved an active user. The handler additionally refuses scoped interview tokens and checks product payments/early-adopter eligibility before accepting work. Audiobook requests are serialized and limited to one per 15 minutes and three per day in D1.
- Queue: `consumeGenerationQueue(batch,env,{styleProcessor:processStyleJob})`. DB and private MEDIA bindings are required. The style processor comes from `cloudflare/api/writing-style.js`.
- Scheduled: `publishGenerationOutbox(env)` recovers interrupted claims and publishes pending intent through `GENERATION_QUEUE`. Run regularly (one minute is suitable). Publishing can duplicate a message after an uncertain acknowledgement; conditional D1 processing claims prevent a second active consumer.
- Cleanup: before deleting an unattached generation object, call `createGenerationRepository(db).cleanupAllowed(objectKey)`. Preserve `media_deletion_jobs` until that returns true. Account deletion should call `cancelForOwner(userId)` and retain the job tombstone/object key until cleanup is safe. Completed EPUB objects are attached media while their completed job belongs to an active account.

Each consumer claim has a random fencing token and a 15-minute lease. A stale claim cannot record completion, count an export, or begin another provider effect. Export accounting and audiobook metadata commit once in the same D1 batch as completion. R2 writes have durable compensation intent reserved first; private keys under `audiobooks/` or `exports/` include both job ID and claim token. A late stale upload cannot overwrite a replacement attempt's completed artifact, and its separate cleanup marker survives completion of the replacement. Incomplete/cancelled work retains cleanup intent with a one-hour safety window for in-flight uploads. This is eventual cleanup, not a cross-service transaction.

EPUB generation is pure and can be retried with the same job key. Canonical input hashes prevent a retry from silently replacing an earlier source snapshot with different text. Audio (and individual style transforms) crosses a paid provider boundary only after D1 records `effect_started`. Provider/network failure, an expired effect, or uncertain publication becomes `needs_reconciliation`; it is never automatically charged or synthesized again. Reconciliation requires an operator/provider investigation and a separate deliberate decision. Do not implement a blind reset-to-queued button for these states.

Audiobook output streams to R2 multipart uploads in 5 MiB parts, with a 200 MiB output limit. Inline cloned-voice samples are bounded to 10 MiB. Fish requests use the fixed official TTS origin, JSON for default narration and MessagePack binary references for cloned narration; multipart/form-data is unsupported by the current provider API. `FISH_AUDIO_API_KEY` is secret. `FISH_AUDIO_MODEL` defaults explicitly to `s2.1-pro`; recognized alternatives are `s2-pro`, `s2.1-pro-free`, and deprecated `s1`. No provider error body, memoir text or secret is logged. Reference samples currently have no stored transcript, matching the source application; hosted voice-quality/provider acceptance remains necessary.

EPUB uses `jszip` and includes escaped canonical prose, reviewed chapters, standalone memories, a contents navigation document and package metadata. It embeds no remote resources. The canonical resolver enforces its documented 8 MiB publishing-input boundary; account data export remains separate. The generated ZIP is local-runtime tested, not externally certified EPUB conformance.

The EPUB HTTP flow is asynchronous: `GET`/`POST /export/epub` returns `202 {jobId}`, `GET /export/jobs/:jobId` polls, and `GET /export/download/:filename` downloads an owner-scoped completed result. Existing audiobook generation/poll/download paths retain that shape. Use a fresh `Idempotency-Key` UUID per intentional generation; repeating the same key/options returns the original job.

Run `node --test cloudflare/api/publishing.test.mjs`. Tests execute against actual local Miniflare D1/R2 with synthetic provider responses and Queue delivery objects. They cover owner/payment/scope/consent denial, canonical EPUB bytes, private downloads, duplicate/concurrent delivery, quotas, claim expiry, uncertain paid effects, deletion/cleanup intent, outbox recovery, style yielding, voice replacement and MessagePack bytes. They do not call paid providers or prove hosted Queue/provider acceptance.
